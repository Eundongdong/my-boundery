# 방문 계획

4단계 기능. 여러 장소의 방문 순서·예상 이동시간·체류시간을 계획하고 Google Maps 경로로 연결.

관련: 02-데이터모델(`visit_plan`), 07-장소검색 §8, 설계서 11장.

## 1. MVP 범위 (설계서 11.1)

- 여러 장소 선택 / 출발 위치 선택 / 방문 날짜·시간 입력
- 장소별 운영시간 확인
- 이동 순서 추천 / 예상 이동시간 / 체류시간(입력 또는 추천) / 전체 소요시간

## 2. 이동 순서 추천 — 최근접 휴리스틱 + 운영시간 제약

- 정식 TSP는 과함. **출발지 기준 최근접 이웃(nearest-neighbor)** 휴리스틱으로 순서 초안.
- 운영시간 제약을 후처리로 반영(닫힌 시간대 방문은 순서 조정·경고).
- 순서는 초안일 뿐 — 사용자가 드래그로 재정렬 가능(승인 프레임: `visit-plan` 요약 카드).

## 3. 예상 이동시간 — MVP는 추정, 정밀은 옵션

- **MVP 기본**: haversine 거리 × 이동수단 평균속도(도보/대중교통/자동차 계수)로 추정. 비용 0.
- **정밀(옵션)**: Google Routes API로 실제 이동시간. 선택 장소 조합에만 호출해 비용 최소화.
- 실제 내비게이션은 **Google Maps 경로 URL**로 위임(키 불필요).

> 하이브리드 원칙과 일치: 렌더·경로표시는 무료, 정밀 계산만 필요 시 유료 API.

## 4. 체류시간

- 사용자가 장소별 입력, 또는 카테고리별 기본값 추천(예: 카페 60분, 클래스 90분, 산책 30분).

## 5. 출력 — 타임라인 (설계서 11.2)

```
14:00 출발 — 집
14:20 OO 공방 도착
14:30~16:00 도자기 클래스
16:00 출발
16:15 OO 카페 도착
16:15~17:15 휴식
17:15 출발
17:30 OO 전시관 도착
```

- 각 구간: 출발–이동–도착–체류. 전체 예상 소요시간 표시.

## 6. Google Maps 연결

- 추천 경로를 Google Maps로 열기(목적지+경유지 dir URL, 07 §8).
- 이동 수단 선택(도보/대중교통/자동차) → URL 파라미터 반영.
- "현재 위치에서 내비게이션 시작"은 Maps 앱에 위임.

## 7. 데이터

`visit_plan`(02-데이터모델): `startLocation`, `plannedDate`,
`stops[{bookmarkId, order, stayMinutes, arriveAt}]`, `totalDurationMin`.
저장은 승인 프레임을 거친다(방문 계획 저장 = 승인 필수 작업).
