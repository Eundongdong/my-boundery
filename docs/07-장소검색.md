# 장소 검색

하이브리드 스택(D7)에서 렌더링은 MapLibre(무료), 장소 데이터는 Google Places로 처리한다.
데이터 모델의 `Place`(마스터, 중복 없음) ↔ `Bookmark`(사용자 저장) 분리를 실제 규칙으로 확정한다.

관련: 02-데이터모델, 04-아키텍처 §2, 설계서 5·6장.

## 1. Places API 버전 — Places API (New)

- 엔드포인트: `https://places.googleapis.com/v1/...`
- **키는 서버 전용** — `/api/places/*` 프록시에서만 사용, 클라이언트 노출 금지.
- **필드 마스크**(`X-Goog-FieldMask`)로 과금 필드를 최소화.

## 2. 검색 방식

| 방식 | 엔드포인트 | 사용처 |
|---|---|---|
| 자동완성 | `places:autocomplete` | 검색창 타이핑, `sessionToken` 과금 묶음 |
| 텍스트 검색 | `places:searchText` | AI 자연어·자유 검색("성수 도자기 공방") |
| 상세 조회 | `GET places/{id}` | 후보 확정 시 상세·좌표 |
| 주변 검색 | `places:searchNearby` | (선택) "내 주변" — MVP는 텍스트로 커버 |

## 3. 결과 위치 편향

- 활성 바운더리 중심+반경으로 `locationBias`(**소프트** 편향).
- `locationRestriction`(하드 제한)은 쓰지 않는다 → 경계 살짝 밖의 좋은 곳도 노출.

## 4. 필드 매핑 (Places New → `place`)

| Google (New) | `place` 필드 |
|---|---|
| `id` | `googlePlaceId` |
| `displayName.text` | `name` |
| `formattedAddress` | `address` |
| `location.latitude` / `location.longitude` | `latitude` / `longitude` |
| `primaryType` / `types[]` | `category` (§5 규칙으로 단순화) |
| `googleMapsUri` | `googleMapsUrl` |
| (조회 시각) | `lastVerifiedAt` |

권장 필드 마스크(텍스트 검색):
`places.id,places.displayName,places.formattedAddress,places.location,places.primaryType,places.primaryTypeDisplayName,places.types,places.googleMapsUri`

## 5. 카테고리 단순화

Google `types` → 우리 표시 카테고리(소수 고정) 매핑, 미매칭 시 `primaryTypeDisplayName` 폴백.

| 표시 카테고리 | Google types 예 |
|---|---|
| 카페 | `cafe`, `coffee_shop` |
| 식당 | `restaurant`, `meal_takeaway`, `bakery` |
| 공방·체험 | `art_studio`, `pottery`, `art_gallery`(체험형) |
| 문화 | `museum`, `art_gallery`, `performing_arts_theater` |
| 운동 | `gym`, `fitness_center`, `yoga_studio` |
| 기타 | 그 외 → `primaryTypeDisplayName` |

> 이 `category`는 **표시용**이다. 사용자 분류는 별개의 **테마**라 충돌하지 않는다.

## 6. Place ID 중복 판정 규칙 (핵심)

```
① googlePlaceId 존재 & 일치
   → 동일 Place 재사용. Bookmark만 추가.
   → 이미 이 사용자가 저장(bookmark 존재)했으면 새로 안 만들고 기존 북마크로 이동.

② googlePlaceId 없음(직접 추가) 또는 신뢰 낮음
   → 좌표 근접(≈30m 이내) + 이름 유사도 높음 → "중복 의심" 후보 제시(삭제형 카드)
   → 병합/신규 여부는 항상 사용자 승인.

③ 가져오기(Takeout)도 동일 규칙 적용 (5단계)
```

DB 이중 안전장치:
- `place.googlePlaceId` **unique**
- `bookmark(userId, placeId)` **unique**

이름 유사도: 정규화(공백·특수문자 제거) 후 부분일치/편집거리 기준(임계값은 구현 시 튜닝).

## 7. 비용 통제

- 자동완성 `sessionToken`으로 상세조회까지 한 세션으로 과금.
- 필드 마스크로 필요한 필드만.
- 조회한 Place 상세는 `place` 테이블에 캐시(중복 API 호출 방지), `lastVerifiedAt` 갱신.
- 오래된 정보(예: `lastVerifiedAt` 30일 초과)는 UI에서 "정보 확인 필요"로 표시(설계서 데이터 품질).

## 8. Google Maps URL (키 불필요)

- 열기: `https://www.google.com/maps/search/?api=1&query=<이름>&query_place_id=<placeId>`
- 경로: `https://www.google.com/maps/dir/?api=1&destination=<좌표>&destination_place_id=<placeId>&waypoints=<경유지들>`
  (방문 계획 4단계에서 활용)

## 9. API 흐름

```
GET  /api/places/autocomplete?q=&sessionToken=&bias=<boundaryId>
POST /api/places/search        { query, bias: boundaryId }
GET  /api/places/:placeId       (상세, 캐시 우선)
```

검색 결과는 저장 전 후보(추가형 카드) → 승인 프레임(06)으로 Bookmark 확정.
