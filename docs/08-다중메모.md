# 다중 메모 UI

결정 D6: **UI는 단일 요약 메모로 시작, 데이터 모델은 처음부터 다중 `Note[]`.**
주제별 다중 메모 UI는 2단계(AI 관리)에서 확장한다.

관련: 02-데이터모델(`note`), 06-AI승인인터페이스, 설계서 7장.

## 1. MVP (1단계) — 단일 대표 메모

- 장소 상세에 메모 1칸(프로토타입 `place-note-editor`).
- 저장 시 `note` 레코드 1개(`topic=null`, `author=user`, `aiStatus=none`)로 저장.
- 자동 저장, 원문은 `originalContent`에 보관.

## 2. 확장 (2단계) — 주제별 다중 메모

장소 상세의 메모 영역을 **대표 메모 + 주제별 메모 리스트**로 확장.

```
장소 상세
 ├─ 대표 메모        (장소 전체 설명, topic=null)
 └─ 주제별 메모
     ├─ 💰 가격    "기본 클래스 45,000원, 재료비 포함"
     ├─ 📅 일정    "토요일 오후 도자기 클래스"
     ├─ ✍ 후기    "강사 친절, 공간은 조금 좁음"
     └─ ➕ 다음 방문 "친구와 머그컵 수업 예약"
```

- `[+ 메모]` → 주제 선택(가격/일정/후기/아이디어/다음방문/직접입력) + 내용.
- 각 메모는 `note` 레코드(`topic` 지정).
- 작성자 구분: `author=user | ai`, 원본 여부 표시.

## 3. AI 메모 정리 (승인 프레임 재사용)

AI가 할 수 있는 정리(설계서 7.3) — 모두 **제안 → 승인**(06 수정형 카드):

- 긴 메모 요약 / 주제별 분리 / 중복 메모 병합
- 할 일·일정·가격·방문 팁 추출
- 장소 평가 요약 / 태그 추천 / 오래된 정보 표시

**원문 보존 규칙:**
- AI는 `originalContent`를 절대 덮어쓰지 않는다.
- 정리 결과는 `aiOrganizedContent`(또는 새 `note` 후보)로 생성, `aiStatus=suggested`.
- 사용자가 승인해야 `aiStatus=approved`, 반영.

예: "긴 메모 하나 → 주제별 3개로 분리" 제안 시, 원문 메모는 유지하고
AI가 만든 3개의 후보 메모를 승인 카드로 보여준 뒤, 승인한 것만 `note`로 저장.

## 4. 범위 밖 (MVP 제외)

- 메모에 이미지·파일 첨부 (미결항목 → 이후 검토)
- 리치 텍스트 서식(프로토타입 툴바는 현재 시각적) — 이후 실제 기능화

## 5. `note` 상태 흐름

```
사용자 작성:  author=user, aiStatus=none
AI 정리 제안: 새 후보 note(author=ai, aiStatus=suggested) 또는 aiOrganizedContent
승인:        aiStatus=approved (원문 note는 그대로 유지)
거절:        후보 폐기 (원문 영향 없음)
```
