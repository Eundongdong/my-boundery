# AI 에이전트 구성

AI는 도구 호출로 작업을 수행하되 **직접 확정하지 않고 구조화된 변경안만 생성**한다.
결과는 `ai_recommendation.proposedChanges`로 저장되어 승인 프레임(06)을 거친다.

관련: 06-AI승인인터페이스, 02-데이터모델, 설계서 9·17장.

## 1. 기본 원칙

- AI는 전체 지도 관리를 보조하지만 데이터를 **확정하지 않는다**.
- 모든 산출물 = 구조화된 변경안 → 사용자 승인 후에만 반영.
- 추천마다 **근거 제공**. 민감한 성향은 임의 추론 금지. 평가가 적을 때 강한 결론 금지(설계서 8.4).
- 사용자 원문 메모를 덮어쓰지 않는다.

## 2. AI 도구 (tool) 정의

| 도구 | 역할 | 산출 |
|---|---|---|
| `search_places` | Google Places 검색(프록시) | 장소 후보(추가형) |
| `find_bookmarks` | 내 저장 장소 검색·필터 | 목록(변경 아님) |
| `find_similar` | 저장 장소와 유사한 곳 | 장소 후보(추가형) |
| `detect_duplicates` | 중복 장소 탐지 | 병합 제안(삭제형) |
| `suggest_themes` | 테마(폴더) 추천 | 분류 제안(수정형) |
| `suggest_tags` | 태그 추천·통합 | 태그 제안(추가/수정형) |
| `organize_notes` | 메모 요약·주제 분리·병합 | 메모 제안(수정형, 원문 보존) |
| `summarize_preferences` | 메모·평가 기반 취향 요약 | 취향 갱신(수정형, 근거 포함) |
| `plan_visit` | 방문 순서·이동시간 | 방문 계획(요약형) |

읽기 도구(`find_bookmarks` 등)는 변경을 만들지 않으므로 승인 불필요.
쓰기로 이어지는 도구는 반드시 `proposedChanges`로만 산출.

## 3. 구조화 응답 스키마 (proposedChanges)

```jsonc
{
  "type": "place-search | folder-suggest | note-organize | dedup | visit-plan | ...",
  "summary": "집 반경 1km · 조용한 카페 3곳을 찾았어요",
  "rationale": "메모·평가에서 '조용함'을 자주 선호",   // 근거
  "items": [
    {
      "op": "add | update | delete | merge",
      "target": { "kind": "bookmark|note|theme|tag|...", "id": "..." },
      "before": { /* update/delete 시 */ },
      "after":  { /* add/update 시 */ },
      "confidence": 0.0
    }
  ]
}
```

- 승인 API는 `items`를 항목별로 반영, `approval_history`에 before/after 기록.
- 카드 형태는 `type`/`op`으로 결정(06 §3·§7).

## 4. 자연어 명령 예시 (설계서 9.3)

- "집 근처에서 이번 주말에 할 수 있는 체험을 찾아줘" → `search_places`
- "저장한 장소 중 평일 저녁에 갈 수 있는 곳만 보여줘" → `find_bookmarks`
- "도자기 관련 장소를 하나의 테마로 묶어줘" → `suggest_themes`
- "최근 메모를 가격·일정·후기로 나눠줘" → `organize_notes`
- "내 평가를 참고해 비슷한 클래스를 추천해줘" → `find_similar`
- "토요일 오후에 세 장소 방문 순서를 짜줘" → `plan_visit`

## 5. 활동 검색 에이전트 연계 (3단계, 설계서 10장)

기존 주변 교육·체험 검색 에이전트를 **장소 발견 엔진**으로 연결.

- 서비스 입력: `{ boundaryId, center, radiusKm, activityTypes, dateRange, preferences }`
- 에이전트 출력: 장소·프로그램·유형·주소·좌표·거리·가격·일정·설명·신청URL·출처·확인시각·추천근거·정보완전성·중복가능성
- 흐름: 검색 요청 → 에이전트 실행 → 후보 반환 → 중복 검사 → 테마·태그·메모 초안 → 후보 카드 → 승인 저장
- 심층 검색은 **비동기 작업 상태 표시**(성능 목표).

## 6. AI 제공자 = Groq (D8′ 확정)

- Groq(무료 티어, OpenAI 호환), 기본 모델 `llama-3.3-70b-versatile`.
- 구조화 출력은 `response_format=json_object`. 클라이언트 `lib/groq.ts`.
- 키(`GROQ_API_KEY`)는 서버 전용, 리포에 커밋하지 않는다(04 §5).

## 7. 안전 경계 (요약)

**하면 안 되는 것**: 승인 없는 저장·삭제·테마 이동·태그 변경·외부 공유·예약·결제,
원문 메모 덮어쓰기, 승인 없는 취향 학습, 여러 에이전트의 자율적 데이터 수정.
