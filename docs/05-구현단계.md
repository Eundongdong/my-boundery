# 구현 단계

1차 설계서 19장의 5단계를 확정 결정에 맞춰 조정했다.
프로토타입이 이미 1단계 UI의 상당 부분(지도·바운더리·테마·목록·메모 데모)을 제공하므로,
1단계는 "프로토타입을 실제 백엔드·인증에 연결"하는 작업이 핵심이다.

## 현재 상태 (프로토타입 반입 완료)

- 3분할 작업실 UI, MapLibre 지도, 바운더리/테마/상태 필터, 장소 목록·상세, 지도 노트
- AI 추천은 **정규식 샘플**(실제 API 미연결), 데이터는 **localStorage**
- Cloudflare Workers + D1 + Drizzle 스캐폴딩(스키마 비어 있음)

## 2단계 — AI 관리 (제안 → 승인)
- [ ] 실제 AI 연결: 자연어 → 구조화 변경안(`ai_recommendation`)
- [ ] AI 장소 검색(Places 도구 호출) → 후보 카드
- [ ] 폴더(테마)·태그 제안, 중복 탐지
- [ ] 메모 정리 제안(원문 보존, `aiOrganizedContent` 분리)
- [ ] **주제별 다중 메모 UI 확장** (모델은 이미 다중)
- [ ] 승인 워크플로우 + `approval_history` + 되돌리기

## 3단계 — 활동 검색 에이전트 연계
- [ ] 기존 주변 교육·체험 검색 에이전트를 장소 발견 엔진으로 연결
- [ ] 서비스 입력 스키마(boundaryId·center·radiusKm·activityTypes·preferences)
- [ ] 결과 검증 + 기존 북마크 중복 검사
- [ ] 장소·프로그램 연결(필요 시 Program 엔터티 재검토)
- [ ] 추천 후보 카드 → 승인 후 저장

## 4단계 — 개인화와 방문 계획
- [ ] 메모·평가 기반 취향 분석(`preference_profile`, 근거·신뢰도 포함, 사용자 공개·수정)
- [ ] 추천 이유 제공
- [ ] 방문 계획: 장소 선택·출발지·날짜·시간
- [ ] 이동 순서·예상 이동시간·체류시간 계산
- [ ] Google Maps 경로 링크(경유지 포함) 생성

## 5단계 — 데이터 이동
- [ ] Google Takeout 파일 가져오기(CSV/JSON/KML 파싱)
- [ ] Place ID 매칭 + 중복 후보 표시 → 승인 후 가져오기
- [ ] CSV/JSON 내보내기
- [ ] Google Maps 공유 링크
- [ ] 중복 병합 도구

## 작업 순서 원칙 (바이브 코딩)
1. **데이터 계층 먼저** — 스키마·마이그레이션·API가 서면 UI를 붙이기 쉽다.
2. **프로토타입 UI 재사용** — 새로 그리지 말고 localStorage 호출부를 API로 교체.
3. **AI는 승인 흐름과 함께** — 제안·미리보기·이력을 한 세트로 구현.
4. **단계마다 동작하는 상태 유지** — 각 단계 끝에 배포 가능한 상태.
