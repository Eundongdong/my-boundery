# AI 대화·승인 인터페이스

서비스 정체성 "AI는 제안만, 사용자가 승인"을 화면으로 못 박는 설계.
프로토타입의 장소 후보 승인 흐름을 **모든 변경유형에 적용되는 일반 프레임**으로 확장한다.

관련: 통합설계서 §2(원칙), 02-데이터모델(`ai_recommendation`·`approval_history`), 설계서 9.2·17장.

## 1. 인터랙션 모델 — 단발 명령형

- 흐름: `사용자 요청 → AI가 변경안 생성 → 변경 전후 표시 → 승인·수정·거절 → 반영 → 이력 기록`
- 채팅 스레드(맥락 누적) 대신, 각 요청·제안을 개별 레코드(`ai_recommendation`)로 저장.
- "다시 요청 / 조건 수정"은 쉽게: 예시 칩, 반경·테마 조정 후 재실행.
- *대안(보류): 대화형 채팅 — MVP엔 과함, 이후 확장.*

## 2. 승인 단위 — 항목별 체크 + 일괄 액션

- 제안된 각 변경 = 체크 가능한 1개 항목.
- 액션: `[전체 승인]` `[선택 승인]` `[항목별 수정]` `[거절]`
- 프로토타입의 후보 체크박스 방식을 모든 변경유형으로 일반화.
- `status`: `pending → approved | rejected | partial`

## 3. 변경유형별 표시

변경 성격에 따라 카드 형태가 달라진다.

### 추가형 (장소 추가, 태그 추가)
- 미저장 후보. 지도엔 **점선 핀**으로 미리보기.
- 후보 카드: 이름·거리·태그·조건일치 이유·AI 메모 초안(수정 가능)·테마 선택.

```
┌─ ✓ 모스 커피룸  · 집에서 7분 ─────────┐
│  #조용함 #콘센트   테마: ☕ 카페 ▾      │
│  조건일치: 대화 소리 적은 1인석         │
│  AI 메모 초안: [수정 가능]              │
└───────────────────────────────────┘
```

### 수정형 (테마 이동, 메모 정리, 태그 통합)
- **이전 → 이후**를 나란히. 변경 부분 하이라이트.
- 메모 정리는 **원문 보존**: 원문은 그대로 두고 AI 정리는 별도(`aiOrganizedContent`).

```
┌─ ✓ "페이퍼컵 성수" 테마 변경 ─────────┐
│  이전:  ♨ 점심 맛집                    │
│  이후:  ☕ 조용한 카페   ← 하이라이트    │
└───────────────────────────────────┘
┌─ ✓ 메모 정리 제안 ────────────────────┐
│  원문(보존):  "토요일 오후 도자기…"     │
│  AI 정리:    주제별로 3개로 분리 ▾      │
└───────────────────────────────────┘
```

### 삭제형 (중복 병합, 미사용 태그 정리)
- 대상과 결과 명시. 무엇이 유지되고 무엇이 사라지는지.

```
┌─ ✓ 중복 의심: "을지데스크"=2건 ───────┐
│  유지: A(별점4)  /  병합·삭제: B        │
└───────────────────────────────────┘
```

## 4. 표시 위치

- 우측 인스펙터에 "AI 제안" 컨텍스트로 표시(프로토타입 계승).
- 대기(pending) 제안이 여럿이면 상단에 가벼운 요약 목록.
- 지도엔 추가형 후보를 점선 핀으로 미리보기, 범례에 "AI 후보".
- 모바일에선 목록/노트 탭 위에 제안 시트.

## 5. 되돌리기(undo)

- 반영 직후 토스트에 **실행취소** 제공.
- 이후엔 `approval_history`에서 되돌리기(`reversible` 플래그로 가능 여부 표시).
- 모든 AI 변경 기록(설계서 17장):
  요청 내용 · 제안한 변경 · 사용자 승인 여부 · 실제 반영된 변경 · 변경 시각 · 되돌리기 가능 여부.

## 6. 승인 필수 작업 (요약)

다음은 반드시 승인을 거친다(설계서 17장):
북마크 추가·삭제, 테마(폴더) 변경, 태그 추가·삭제, 메모 수정, 평가 기반 취향 갱신,
외부 데이터 가져오기, 데이터 내보내기, 방문 계획 저장.

AI가 자동으로 하면 안 되는 것: 승인 없는 저장·삭제·이동, 원문 메모 덮어쓰기,
승인 없는 태그 변경·외부 공유·예약·결제.

## 7. `ai_recommendation.type` ↔ 카드 형태 매핑

| type | 형태 | 되돌리기 |
|---|---|---|
| `place-search` | 추가형(후보 카드) | 삭제로 취소 |
| `tag-suggest` | 추가형/수정형 | 태그 원복 |
| `folder-suggest` (테마 이동) | 수정형(이전→이후) | 이전 테마 복원 |
| `note-organize` | 수정형(원문 보존) | AI 정리 폐기 |
| `dedup` | 삭제형(병합) | 병합 해제(가능 시) |
| `visit-plan` | 요약형(일정 미리보기) | 계획 삭제 |
| `preference-update` | 수정형(취향 근거 표시) | 취향 항목 복원 |

## 8. API 흐름

```
POST /api/ai/recommend   { type, inputContext }
   → ai_recommendation(status=pending, proposedChanges) 생성·반환

POST /api/ai/approve      { recommendationId, itemIds[]?, edits? }
   → 선택 항목만 반영, approval_history 기록, status 갱신
   → 반영 결과 반환(되돌리기 토큰 포함)

POST /api/ai/revert       { approvalHistoryId }
   → reversible 항목 되돌리기
```
