# 데이터 모델 설계

- 저장소: Cloudflare D1 (SQLite) + Drizzle ORM (결정 D8)
- 거리 계산: 애플리케이션 레벨 haversine (PostGIS 미사용)
- 원칙: 출처·확인 시각 기록, 원문 보존, 승인 이력 연결 (통합설계서 §2)

## 1. 엔터티 관계 개요

```
User
 ├── Boundary        (다중 바운더리, 단일 지도 위 오버레이)
 ├── Theme           (테마 = 폴더 역할, 장소당 1개 연결)
 ├── Place           (장소 마스터, Google Place ID로 중복 판정)
 ├── Bookmark        (User가 Place를 저장한 관계 + 상태·별점·저장이유)
 │    ├── Note[]     (장소별 다중 주제 메모, 원문/AI정리 구분)
 │    └── (Rating은 Bookmark 필드로 인라인)
 ├── MapNote         (지도 전체 노트 + 체크리스트)
 ├── VisitPlan       (방문 계획, 4단계)
 ├── PreferenceProfile (메모·평가 기반 취향 요약)
 ├── AIRecommendation  (AI 제안, 승인 전 변경안 저장)
 └── ApprovalHistory   (승인·반영 이력, 되돌리기)
```

핵심: **Place는 마스터(중복 없음), Bookmark는 사용자-장소 저장 관계.**
같은 Google Place ID면 Place는 하나만 두고, 사용자별 저장 정보는 Bookmark에 담는다.
(데이터 품질 기준: "동일 Google Place ID는 중복 장소로 저장되지 않는다")

`Bookmark`는 `boundaryId`를 갖되, 한 장소를 여러 바운더리에 노출하려면 반경 안에 들어오는지로
판정(오버레이 필터) — 명시적 소속은 대표 바운더리 1개, 표시는 반경 기준. (결정 D1)

## 3. 중복 판정 규칙 (초안 — 다음 라운드 확정)

1. `googlePlaceId`가 같으면 동일 Place → Place 재사용, Bookmark만 추가.
2. `googlePlaceId`가 없으면(직접 추가) 좌표 근접(예: 30m 이내) + 이름 유사도로 후보 제시.
3. 최종 병합은 항상 사용자 승인.

## 4. 프로토타입 타입 → 모델 매핑

프로토타입 `BoundaryStudio.tsx`의 로컬 타입을 DB 모델로 옮길 때의 대응:

| 프로토타입 타입 | 모델 |
|---|---|
| `Boundary` (home/work 고정) | `boundary` (사용자 생성 가능하게 일반화) |
| `Theme` | `theme` |
| `Place` (themeId·tags·reason·status·rating·note 인라인) | `place` + `bookmark`(+`note`)로 정규화 |
| `MapNote` | `map_note` |
| `AiCandidate` / `AiSuggestionSession` | `ai_recommendation`(proposedChanges) |
| localStorage `PersistedState` | D1 테이블 + 사용자 스코프 |
