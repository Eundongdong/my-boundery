# 인증·계정

Google 로그인 전용. 모든 데이터는 사용자 스코프. 프로토타입의 ChatGPT 인증을 대체한다.

관련: 02-데이터모델(`user`), 04-아키텍처 §4·5, 설계서 16장.

## 1. 인증 방식 — Google OAuth 2.0

- Auth.js(NextAuth) 호환 계층, Cloudflare Workers 런타임에서 동작.
- 스코프는 **최소**: `openid`, `email`, `profile`.
  - Google Maps/Places는 **서버 API 키**로 호출 → 사용자 OAuth 스코프와 무관.
  - Takeout 가져오기는 **파일 업로드** 방식이라 Google 계정 데이터 접근 스코프 불필요(D3·5단계와 일치).
- 프로토타입 `app/chatgpt-auth.ts`는 제거/대체.

## 2. 사용자 식별·생성

- `user.googleAccountId` = Google `sub`(안정적 식별자), unique.
- 최초 로그인 시 `user` 생성(email·displayName 저장).
- 이메일 변경에도 `sub`는 유지되므로 `sub` 기준으로 계정 연결.

## 3. 세션 — 서명된 httpOnly 쿠키(무상태 JWT)

- Workers 환경에 맞게 **무상태 JWT 세션 쿠키**(httpOnly, Secure, SameSite=Lax).
- `AUTH_SECRET`로 서명. 필요 시 D1 세션 테이블로 전환 가능(선택).
- CSRF: SameSite + OAuth state 파라미터.

## 4. 데이터 소유권·접근 제어

- 모든 쿼리는 세션 `userId` 스코프. 서버에서 요청 사용자와 리소스 소유자 대조.
- 공유 없음(D3) → 교차 사용자 접근 경로 자체를 두지 않는다.
- 삭제: 사용자가 계정·데이터 삭제 요청 시 관련 레코드 일괄 삭제(개인정보 원칙).

## 5. 시크릿 (커밋 금지 — 04 §5)

- `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET`
- `AUTH_SECRET`
- (Places용) `GOOGLE_MAPS_API_KEY` — 서버 전용

## 6. 로그인 흐름

```
[로그인] → Google OAuth 동의 → 콜백(/api/auth/callback)
  → sub로 user 조회/생성 → 세션 쿠키 발급
  → 온보딩(첫 바운더리 생성) 또는 메인 지도로
```

온보딩(설계서 13.1): Google 로그인 → 첫 바운더리 생성(주소·반경) → 관심 테마 선택 → 첫 장소 추가 안내.
