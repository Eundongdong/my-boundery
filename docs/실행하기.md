# 로컬 실행 가이드

## 사전 준비
- Node.js **22.13 이상** (`node -v`)
- pnpm (`corepack enable && corepack prepare pnpm@latest --activate`)

## 옵션 A — 데모 모드 (키 불필요)

localStorage + MapLibre(키 불필요)로 UI·지도·샘플 동작을 바로 볼 수 있다.

```bash
pnpm install
pnpm dev        # Windows PowerShell: $env:WRANGLER_LOG_PATH=".wrangler/wrangler.log"; pnpm exec vinext dev
```
터미널에 찍힌 `http://localhost:5173`(포트는 다를 수 있음)을 **일반 데스크톱 브라우저**에서 연다.
상단바에 "데모 모드" 배지가 보이면 정상.

> `pnpm dev` 실행 시 `write EOF` 오류가 나면 workerd 빌드 스크립트가 차단된 것.
> `pnpm approve-builds` 로 workerd 를 허용하거나, 이 프로젝트는 `package.json` 의
> `pnpm.onlyBuiltDependencies` 로 자동 허용되므로 `pnpm install` 을 다시 실행한다.

## 옵션 B — 로그인 + 서버 동기화

### 1) 환경변수
`.dev.vars.example` 을 복사해 `.dev.vars` 를 만들고 값을 채운다. (`.dev.vars` 는 커밋 금지)

```
AUTH_SECRET=<긴 랜덤 문자열>
APP_URL=http://localhost:5173
GOOGLE_OAUTH_CLIENT_ID=...
GOOGLE_OAUTH_CLIENT_SECRET=...
GOOGLE_MAPS_API_KEY=...
```

### 2) Google Cloud
- **OAuth 동의화면**: 테스트 모드면 본인 계정을 **테스트 사용자**로 추가.
- **OAuth 클라이언트**:
  - 승인된 리디렉션 URI: `http://localhost:5173/api/auth/callback`
  - 승인된 JavaScript 원본: `http://localhost:5173`
  - (dev 서버 포트가 다르면 그 포트로 맞춘다. `APP_URL` 도 동일하게)
- **API 사용 설정**: Places API (New), Geocoding API.

### 3) 로컬 D1 마이그레이션 적용 (최초 1회)
dev 서버를 끈 상태에서:
```bash
pnpm db:migrate:local
```
`user`/`boundary`/`bookmark` … 11개 테이블이 생성된다.
(`wrangler.d1.jsonc` 설정 사용. dev 서버와 같은 로컬 D1 을 가리킨다.)

### 4) 실행 후 로그인
```bash
pnpm dev
```
"Google로 로그인" → 콜백 후 `user` 생성 → 온보딩(첫 바운더리 만들기).

## 자주 겪는 문제
- **로그인 후 `no such table` / `Failed query: ... from "user"`** → 3) 마이그레이션 미적용. `pnpm db:migrate:local` 실행.
- **구글 동의 페이지 로드 실패(-356)** → 앱 내장/미리보기 브라우저에서 열었을 때. 일반 Chrome/Edge 로 접속.
- **`redirect_uri_mismatch`** → 리디렉션 URI/포트와 `APP_URL` 불일치.
- **마이그레이션은 됐는데 dev 에서 여전히 테이블 없음** → CLI와 dev 서버가 다른 로컬 상태를 볼 때. `--persist-to` 로 경로를 맞춘다.
